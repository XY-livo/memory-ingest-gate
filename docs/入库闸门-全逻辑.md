# 入库闸门 · 全逻辑

> 本文件是设计说明；可直接跑的实现见 `src/gate.py`（`python3 src/gate.py selftest`）。

> 一句话：**库只装"下次还用得上的判断"，不装过程。** 闸门的职责是把"看起来像结论的东西"逼到能被检验的形态，再按证据强弱分流。

库：`<vault>`｜工具：`src/gate.py`（Python 3，零依赖）｜使用约定：（本仓 docs/ 为准）

---

## 一、写之前：两个固定动作（不是可选）

```
python src/gate.py similar "一句话描述你要记的事"   # 像不像已有条目
python src/gate.py entity E02                       # 这个实体的全部记录
```

- **命中已有** → 合并，或做等级升降级，**不新增**
- **命不中** → 才写

> 理由：重复条目是检索质量的头号杀手，且重复往往带着"其实同一件事的两个说法"。

---

## 二、一条主张必填七项

| 字段 | 含义 | 不合格会怎样 |
|---|---|---|
| `layer` | L0 规则 / L1 证据 / L2 关联 / L3 场景 / L4 项目 / L5 个人 | 不在枚举内直接拒 |
| `subject` | 实体编号（E01…），**必须先在 `_实体表.md` 登记** | 「实体未登记」拒收，并列出已知实体 |
| `relation` | 关系（规定/决定/认为/就职于…） | 空即拒 |
| `object` | 值（结论本身） | 空即拒 |
| `condition` | 在什么条件下成立 | 不同 condition 不算冲突（V0 例外，见下） |
| `valid_from`（+`valid_to`、`precision`） | 有效区间；precision=日/月/年/约 | 空即拒 |
| `source` + `source_ref` | 来源；**source_ref 必须能定位**：`inbox/a.md#L12` 或 `event:2026-11-03 21:35` | 定位不到即拒 |
| `level` + `level_by` | 证据等级与定级人 | 等级非法/越权即拒 |

**另有两条按类追加**
- **规定类必须有 `dimension`**（层级/容量上限/实体表/用途/来源…）：没有维度就分不清"同一件事的两种说法"还是"并行的两件事"
- **必须有 `use_when`**（将来什么时候会用到）——唯一豁免：`relation=规定 且 level=V0`（宪法级，只有本人能写）

---

## 三、过闸顺序（代码实际执行顺序，顺序本身是逻辑）

```
① 校验：必填 → 实体已登记 → 日期展开 → source_ref 可定位 → level 合法 → layer 合法 → V0 定级人
② 重复判：同实体 + 同关系 + 同值 + 区间重叠        → 拒收，返回 existing id（不建新条）
③ 冲突判：同实体 + 同关系 + 同维度 + 值不同 + 区间重叠
        ├─ condition 不同 → 视为可并存（coexist_with 记一笔）
        └─ 但任一方是 V0 → condition 不构成并存理由 → 一律 needs_review（必须人审）
④ 用途闸：非"规定+V0"且没写 use_when → 进候选区（candidate），不进主库
⑤ 等级分流：V3 → 候选区（id 前缀改 N-）；V4 → 状态 refuted；其余 → active 入 claims/
```

> 注意 ②③ 在 ④⑤ 之前：**先判重、再判冲突，最后才谈等级**。反过来会把"重复"当"冲突"塞进队列。

---

## 四、五个状态 + 一个前缀

| 状态 | 在哪 | 含义 |
|---|---|---|
| `active` | `claims/` | 正常可用 |
| `candidate` | `queue/` | 缺 `use_when`，或 V3 未证实；只作参考 |
| `pending` | `queue/` | 有冲突待裁决（普通） |
| `needs_review` | `queue/` | 冲突且涉及 V0（宪法级）→ 必须人审 |
| `refuted` | `claims/` | 已被证伪（V4），召回默认不带 |
| `superseded` | — | 冲突裁决后退役（旧值保留，可追溯） |

`N-` 前缀 = 候选区条目（V3），检索时标注"未证实"。

---

## 五、等级体系：五档 + 四条硬规则

| 级 | 含义 | 谁能定 |
|---|---|---|
| **V0** | 本人定的规则（宪法级） | **只有本人**；agent 写 V0 直接被拒 |
| **V1** | 已证实（本机可复现） | agent 可给，但 `verify` 必须写清「怎么跑、输出是什么」 |
| **V2** | 侧面证实（文档/网页/他人转述） | agent 最高到 V2（规则类/偏好类） |
| **V3** | 未证实 | 只进候选区 |
| **V4** | 已证伪 | 状态转 refuted，检索默认排除 |

**四条硬规则**
1. **V0 只有本人能写**：`level_by` 里没有本人名字 → 拒
2. **升级每步只许一级**：V3→V2→V1→V0；跳级直接拒，并告诉你"本次最多到哪"
3. **降级 agent 一律拒**：只有本人带 `--by 本人` 才能降，且同样每步一级，并往该条 `## History` 追加一行（日期｜旧→新｜by｜依据）
4. **越靠"事实"越硬，越靠"偏好"越软**：同一句话，能复现才算 V1，不能复现一律降档

---

## 六、冲突：不静默覆盖，一律进队列

- 队列项三种裁决：`keep-a` / `keep-b` / `keep-both`
- 裁决后：败方状态 → `superseded`，并写 History（谁、何时、为什么）
- **V0 一旦卷入冲突**：`condition` 差异不许把冲突"洗成并存"，强制进 `needs_review`
- 线索都留在条目自己的 `## History` 里，不另开等级日志——**四要素（谁/何时/旧值/为什么）随条目一起被读**

---

## 七、每次过闸实际会看到的输出（判读口径）

| 输出 | 含义 | 下一步 |
|---|---|---|
| `{"ok":true,"status":"active","similar":[...]}` | 入主库成功；`similar` 是提醒你还有相近条目 | 视需要合并 |
| `{"ok":false,"reason":"duplicate","existing":"C-…"}` | 已有同值同区间条目 | **去改那条**，别新增 |
| `{"ok":true,"status":"pending","queued_conflict":"Q-…"}` | 与旧值冲突，已进队列 | 等裁决；不许自己选 |
| `{"ok":true,"status":"needs_review"}` | 冲突涉及 V0 | 必须人审 |
| `{"ok":true,"status":"candidate","why":"缺 use_when…"}` | 写不出用途 | 补 `use_when` 再重提 |
| `{"ok":true,"status":"candidate","why":"V3…"}` | 未证实 | 只作参考 |
| `异常退出 "缺必填：…" / "实体未登记…" / "V0 只能由本人本人定"` | 闸门拒绝 | 按提示补，别绕 |

## 八、红线（写死在规矩里，不是建议）

1. **原件不可改**：`inbox/` 写入即不可变；要改就重收一份
2. **V0 只能本人写**；agent 最多给 V2 建议
3. **冲突不静默覆盖**：一律进队列等人裁决
4. **没有 `source_ref` / `verify` 依据的，不许进 claims**；V3 只进候选区
5. **收工只写「结论 + 依据」**，不写过程
6. **什么不该入库**：文件清单、进度（"已移走 12 项"）、中间草稿、日志 → 这些归待办/工单
   > 原因：库一旦装运行时数据，检索会被日志淹没

---

## 九、为什么是这些闸（每条都对应一次真实踩坑）

| 闸 | 没有它会怎样 |
|---|---|
| 实体必须先登记 | 同一个人出现三种写法，检索全漏 |
| source_ref 可定位 | 结论无法回溯，等于道听途说 |
| 重复判（先于冲突判） | 重复被当冲突，队列里全是自己跟自己打架 |
| dimension（规定类） | 两件并行的事被判成"同一件事的两种说法"，互相洗掉 |
| use_when | 库变成"发生过什么"的流水账，下次用不上 |
| V3 只进候选区 | 未证实的东西和已证实的混在一起被当依据 |
| V0 人审 | 规则级冲突被"条件不同"自动洗过 |
| 降级只有人能降 | agent 心情一坏就把结论降档，历史不可信 |

## 十、一页速查

```
写前：similar + entity（命中就改，不新增）
七项：layer / subject / relation / object / condition / 区间 / source+ref / level+level_by
追加：规定类要 dimension；除「规定+V0」外都要 use_when
顺序：校验 → 重复 → 冲突 → 用途 → 等级分流
等级：V0 只有本人 / 升级每步一级 / 降级 agent 免谈 / V4 自动 refuted
冲突：进 queue，三选一裁决，败方 superseded 并写 History
红线：原件不改、冲突不覆盖、无出处不入库、只写结论不写过程
```
