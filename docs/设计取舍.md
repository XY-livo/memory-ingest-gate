# 设计取舍（为什么不那样做）

## 1. 为什么不用向量检索
向量解决「意思相近」，解决不了「该不该信、能不能回溯」。
闸门在**进门之前**工作：先把条目逼到可检验的形态，再用任何检索方式都行。
把两件事混在一起，最后变成「检索很聪明，库里全是垃圾」。

## 2. 为什么等级只有五档，且升级一次一级
等级不是标签，是**承诺**：V1 意味着"我能在本机复现"。
允许跳级，就等于允许"听说"一夜之间变成"证实"。
一次一级 + 每次留痕，历史才可信。

## 3. 为什么降级只有人能降
agent 的"心情"会变（换了模型、换了提示词、上下文截断）。
如果 agent 能降级，那么昨天 V1 的结论今天可能悄悄变成 V3——
不是因为它错了，而是因为没有人在看。降级是**权力**，不是操作。

## 4. 为什么重复判必须在冲突判之前
同一件事被写成两条，本来只是重复；先判冲突就会把它塞进待裁决队列，
队列里全是"自己跟自己打架"，人一旦烦了就开始乱点。

## 5. 为什么规定类必须有 dimension
没有维度，"两个人对同一件事的两种说法"和"两件并行的事"长得一模一样。
dimension 是给冲突判据的一个坐标轴，没有它，冲突判定只能靠猜。

## 6. 为什么 V3 只进候选区
未证实不是"差一点"，是"另一种东西"。
把它和已证实放在一起，用户会默认它也可信——这是最贵的错误。

## 7. 为什么不存过程和日志
过程会过期，结论不会。库一旦装日志，检索就被淹没，
而且要回答"上次怎么做的"应该去工单/日志，不是去知识库。

## 8. 为什么不内置冲突自动裁决
自动裁决需要"谁更对"的判断，而这恰恰是闸门**不该**拥有的权力。
闸门只负责"把冲突摆到人面前，并且不让它被悄悄覆盖"。
